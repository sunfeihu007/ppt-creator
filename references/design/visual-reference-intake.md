# 视觉参考导入与晋级

当用户提供网站截图、PPT 截图、设计链接或配色参考并要求丰富 PPT Creator 时，先建立候选
提案，不直接修改正式 palette/style 注册表。

## 一、先判断资源类型

| 用户真正喜欢的部分 | 候选类型 | 最低证据 |
|:---|:---|:---|
| 颜色角色、明暗关系、强调色 | `palette` | 1 张高清图；最好附原网址 |
| 单页构图、某种模块排列 | `layout` | 1 张图＋对应 `page_type` |
| 字体、网格、材质、图片和多类页面的统一语言 | `style` | 至少 4 张图＋4 种 `page_type` |
| 只对某行业成立的几何、图像或语气 | `industry` | 多页面、多项目证据 |
| 客户 Logo、品牌色或企业模板 | 项目品牌覆盖 | 不进入通用库 |

单张截图不能证明整套 style。网站截图只转化静态视觉：颜色、字体、网格、材质、对齐、
图片处理和空间锚点；不把导航、悬停、手势、动效或响应式行为搬进 PPT。

## 二、建立候选记录

优先使用原图或原始 PPT，避免聊天软件压缩。记录来源网址，并让用户指出具体喜欢和不喜欢
的部分；不要靠 agent 猜测“高级感”来自哪里。

```bash
python scripts/intake_visual_reference.py \
  --source /absolute/path/reference.png \
  --source-url https://example.com/original \
  --liked "喜欢瓷白背景、石墨结构和单一晴蓝聚焦" \
  --scope auto \
  --output /absolute/path/visual-reference-proposal.json
```

完整风格候选为每张图重复 `--source`，并为代表页面重复
`--page-type cover --page-type overview --page-type architecture --page-type detail`。

脚本只记录哈希、尺寸、来源和用户偏好，不复制图片像素，不改正式注册表，并固定输出
`promotion_ready=false`。视觉提取、查重、通用性判断和晋级必须由 agent 与用户共同完成。

## 三、提取规则

### Palette

- 提取背景、表面、结构、聚焦、可读文字、边界、反相和状态语义；
- 补齐 16 个语义 Token 与旧兼容 Token；
- 检查文字角色在背景和表面上至少达到 4.5:1；
- 不复制动态系统色、客户品牌色或截图压缩后的偶然色偏；
- 与现有 palette 比较：如果主要差异只是一处明度或饱和度，作为项目覆盖，不新增全局 palette。

### Style

- 提取密度、变化范围、几何、圆角、阴影、材质、图片、注释、微标签和字体治理；
- 至少覆盖封面、总览、架构/流程、详解四类页面；
- 用至少三个行业或通用场景检查适用性；
- 如果与现有 style 高度重合，增强现有治理或登记单页布局，不新增同义 style。

## 四、去品牌与去污染

- 不保存或传播客户 Logo、客户名称、受版权保护的原始像素、假指标或界面文字；
- 来源图只作分析证据；正式参考图重新生成；
- 正式参考图保持无文字、无品牌、无数据、无 EXIF；
- 设计方法可以吸收，原始模板、专有组件和品牌资产不能直接复制。

## 五、晋级 Gate

候选资源只有同时满足以下条件才可进入正式系统：

1. 用户确认候选类型和喜欢的视觉维度；
2. 与现有 13 套 palette / 9 种 style 完成差异审查；
3. 完成跨行业通用性审查；
4. palette 补齐语义 Token 与对比度；style 补齐治理 profile；
5. 生成封面、架构、详解三页无品牌样张并目检；
6. 用户明确批准样张；
7. 补齐全部 palette × style 兼容状态；
8. 运行 `validate_design.py`、`generate_style_refs.py --check` 和完整测试。

没有通过 Gate 时，把方案留在项目工作区的候选 JSON 中；不要创建半注册资源，也不要让
提示词自动读取候选文件。
