# 三轮内容规划与对话操作

## 第一轮：需求理解与大块确认

先读取用户已给的素材，提取主题、对象、事实、争议和决策问题。只询问尚未明确且影响方案的
场景、受众、目标、时长/页数约束、已有材料与强调点。用户未指定时提出合理建议并标注假设。
页数由信息量与演讲时长共同决定，不按分钟数机械乘倍数。

先起草整套 `deck`，再起草 `sections`：

- 整套：核心问题、目标、核心主张、听众应记住的2–3件事、重点、范围、叙事主线。
- 每大块：主题、主旨、重点、在全篇的作用与优先级。
- 大块关系：从哪块到哪块、何种关系、为何如此、为何按这个顺序讲。

推荐展示形式：

> 这套演示希望让【受众】从【当前判断】走向【目标判断/行动】。核心主张是【一句话】。
>
> 大块 A：主题｜主旨｜全篇作用｜核心重点
> 大块 B：主题｜主旨｜全篇作用｜核心重点
> 逻辑：A → B（关系类型，因为……）
>
> 本次最需要您确认的是核心主张和分块顺序；若调整，请指出应保留、删去或加强的块。

保存 `draft_plan.json`，用 `init` 建立正式工作文件，此时 `blocks/pages` 可为空。
先 `lint --stage outline`，用户确认后 `confirm --stage outline`，再展开下一轮。
如用户只要先看方案，可继续写完整草稿，但不伪造确认。

## 第二轮：小块内容与关系确认

逐大块提出2–4个小块作为起点，必要时调整。每小块至少写清：

- 所回答的问题和明确主旨；
- 核心重点与支撑要点；
- 在所属大块、在整套 PPT 中分别承担什么作用；
- 优先级，以及它与同层小块、跨块关联内容的关系。

先从最关键主张反推必需的证据，不把材料目录照搬为内容结构。
核对来源是否足够支持主张；未证实的事实记为待补证，推演记为假设。
同步记录需求、禁止用语、声明边界、来源和阻塞问题。

展示完整的小块树和有理由的关系链，再合并确认。`update` 保存内容补丁（sections 数组需完整提供），
运行 `lint --stage content`；收到确认后记录 `confirm --stage content`。

## 第三轮：逐页规划与整套确认

逐页分配依据是内容主旨，而不是封面/目录/卡片模板。每页归属于一个小块；页面数组就是最终讲述顺序。
允许为承上启下回访前面的内容，但必须在角色和衔接说明中解释，不依赖层级树推断播放顺序。

每页填写：主题标题、一句话主旨、核心重点、优先级、听众问题、全篇作用、所属小块作用、
具体要点、证据/假设、信息实体与关系、阅读顺序、讲述提示、时长、承接下一页。
若准备以信息图表达，先说明“对象之间是什么关系、图要传达什么”，不提前挑模板。

自检：

1. 每个小块都落到了具体页面吗？重点内容分配到足够的论证空间了吗？
2. 每页主旨是否明确且必要？这页被删除会失去什么？
3. 相邻页面的关系能一句话说清吗？论据是否先于依赖它的结论出现？
4. 大块和小块的逻辑关系、页内因果关系是否有依据？并列不应被误标为因果。
5. 量化信息是否有来源、单位和比较口径？真实案例与方案假设是否明确区分？
6. 每页信息结构是否能交给设计师理解，而无须重新猜测对象含义与关系？
7. 总时长与用户约束是否匹配？重点、支撑、背景是否真的有区别？

运行 `lint --stage pages`，处理 errors，向用户解释需要注意的 warnings。
先 `export --draft` 提供完整 Markdown 和 HTML，邀请用户合并确认逐页内容。
只对真正有歧义的内容单独提问，不逐页索取审批。
确认后运行 `confirm --stage pages`、`export`、`check-export`，交付已确认内容和下一阶段边界。

## 回改、失效与恢复

`plan.json` 是事实源。改页使用 `page --patch`，改其他内容使用 `update`。补丁对象递归合并，
数组是整体替换，不是按 id 自动合并；发送补丁前保留完整数组内容，避免误删未涉及的节点。

确认指纹按层级检查：改逐页内容通常只影响第三轮；改小块影响第二、三轮；改整套主张或大块影响三轮。
来源和声明约束属于第二轮，其变化会影响第二、三轮。更改后用 `status` 查看实际失效范围。
旧确认依据保留用于追溯，但不再代表对新内容的批准；手动编辑 JSON 也会被指纹识别。

任何草稿均可导出预览。带 `--draft` 的文件始终标为草稿，即使三轮已确认，也不会冒充正式交接。
HTML 中的展开、搜索、点击不修改计划，也不视为批准。
